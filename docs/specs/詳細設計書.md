# 詳細設計書

対象アプリ：**TKS OLAP to kintone**（v1.4.16）

> 各機能の処理フロー・使用関数・入出力・例外処理をソースコードから整理する。推測箇所は明記する。

---

## 1. アプリ起動処理

### 概要
`app/main.py` のエントリポイントから GUI を起動する。

### 処理フロー
1. `python -m app.main` / EXE 実行で `main()` が呼ばれる。
2. パッケージ未指定時は親ディレクトリを `sys.path` へ追加。
3. `app.gui.run_gui()` を呼ぶ。
4. `run_gui` が `QApplication` を生成し、保存テーマを `apply_theme` で適用。
5. `LauncherWindow` を生成・表示し、Qtイベントループ開始。
6. 二重起動要求時は `activate_existing_window`（既存ウィンドウ前面化）。

### 使用クラス・関数
| ファイル | クラス／関数 | 役割 |
| --- | --- | --- |
| app/main.py | `main` | エントリポイント |
| app/gui.py | `run_gui` | QApplication生成・LauncherWindow起動 |
| app/launcher_window.py | `LauncherWindow.__init__` | 入口画面構築 |

### 入力／出力
- 入力：起動引数、保存テーマ（QSettings）。
- 出力：GUI表示、終了コード。

### エラー処理
- 起動時の致命的エラーは例外伝播（推測：個別ハンドリングは限定的）。

### 注意点
- EXE（PyInstaller）では `sys._MEIPASS` を基準にリソースを解決（`resource_path`）。

## 2. 設定ロード処理

### 概要
ProgramData配下の `config.env` / `field_mapping.json` を読み込み `AppConfig` を構築する。`app/config.py`

### 処理フロー
1. `default_base_dir()` で ProgramData 配下（`%PROGRAMDATA%/Manekiya/TksToKintone`）を取得。
2. `ensure_olap_templates_installed()` で同梱OLAPテンプレートを ProgramData へ配置（古ければ上書き）。
3. `config.env` / `field_mapping.json` が無ければ sample からコピー（`_ensure_from_sample`）。
4. `TKS_VOUCHER_OLAP_ENABLED_OP_FIELDS` を未設定なら追記（`_ensure_op_fields_in_config`）。
5. `dotenv_values` で値を読み込み、work/log/error 等のパスを構築。
6. `ensure_default_initial_data()` で加工名マスタ・得意先ヘッダーの初期投入。
7. `TKS_CLIENT_MODE`（mock/http）に応じ必須キーを検証。
8. 得意先表示名・判定文字列・プレビューテーマを読み込み `AppConfig` を生成。

### 使用クラス・関数
| ファイル | クラス／関数 | 役割 |
| --- | --- | --- |
| app/config.py | `load_app_config` | 設定読込・検証 |
| app/config.py | `ensure_olap_templates_installed` | OLAPテンプレ再配置 |
| app/config.py | `update_values_in_config` / `update_customer_labels_in_config` | config.env更新 |
| app/settings_service.py | `ensure_default_initial_data` | 初期データ投入 |
| app/models.py | `AppConfig` / `AppPaths` | 設定データクラス |

### 入力／出力
- 入力：`config.env`, `field_mapping.json`, 同梱 sample。
- 出力：`AppConfig`、各フォルダ作成。

### エラー処理
- 必須キー不足・sample欠如・`TKS_CLIENT_MODE`不正で `ConfigError` を送出。

### 注意点
- `KINTONE_DOMAIN` は `https://`/`http://`・末尾`/`を除去して保持。
- パスは相対なら base_dir 基準で解決（`_resolve_child`）。

## 3. OLAPログイン処理

### 概要
TKS OLAP へHTTPログイン認証する。`app/tks_client.py`（`HttpTksClient.login`）。mockモードはスキップ。

### 処理フロー
1. `create_tks_client(config, logger)` でモード別クライアント生成。
2. http：`/c/ログイン認証` へ POST（ログインpayload）。
3. レスポンスの `ResponseData.Ｘ0`(=`X0`) が `00` なら成功、それ以外は失敗。
4. `.ASPXAUTH` Cookie取得有無をログ出力。
5. リクエスト/レスポンスをデバッグJSONとして保存（パスワードはマスク）。

### 使用クラス・関数
| ファイル | クラス／関数 | 役割 |
| --- | --- | --- |
| app/tks_client.py | `create_tks_client` | クライアント生成 |
| app/tks_client.py | `HttpTksClient.login` / `MockTksClient.login` | ログイン |
| app/launcher_window.py | `_verify_olap_login` | 認証チェック |

### 入力／出力
- 入力：`RunInput`（company_code, ログインID/PW）。
- 出力：認証Cookie（セッション内）、デバッグJSON。

### エラー処理
- `X0 != "00"` / `ResponseData` 欠如で `RuntimeError`（失敗内容＋デバッグパスを含む）。

### 注意点
- ログイン認証区分（`TKS_LOGIN_AUTH_KBN`）、端末識別ID等を config から送る。

## 4. OLAPデータ取得処理

### 概要
受注NoごとにOLAPデータ（伝票/加工/取引区分）を取得する。`app/voucher_olap_service.py`（伝票画面）／`app/tks_client.py`（Kintone登録のCSV取得）。

### 処理フロー（伝票画面 VoucherOlapService）
1. `login_if_needed()` で未認証なら認証。
2. `_build_voucher_payload(order_no, ...)` でテンプレートのR2条件に受注Noを差し込む。
3. `/c/OLAPデータ` へ PUT。
4. `_extract_voucher_rows_or_raise` でR1行を抽出。0件なら `OlapNoDataError`。
5. `_enrich_transaction_types` で得意先コード→取引区分を別テーブル取得・付与（得意先コード単位でキャッシュ）。

### 処理フロー（Kintone登録 tks_client）
1. `fetch_csvs` で加工抽出/素板抽出CSVをOLAPから取得（mockはfile://）。
2. 取得CSVを後段のCSV変換へ渡す。

### 使用クラス・関数
| ファイル | クラス／関数 | 役割 |
| --- | --- | --- |
| app/voucher_olap_service.py | `fetch_vouchers` / `fetch_voucher_rows` | 伝票OLAP取得 |
| app/voucher_olap_service.py | `fetch_transaction_type_by_customer_code` / `parse_transaction_type` | 取引区分取得 |
| app/voucher_olap_service.py | `_build_voucher_payload` / `build_transaction_type_payload` | payload生成 |
| app/tks_client.py | `fetch_csvs` | 加工/素板CSV取得 |
| app/voucher_data_mapper.py | `extract_r1_rows` | R1行抽出 |

### 入力／出力
- 入力：受注No、OLAPテンプレート、認証Cookie。
- 出力：R1行（dict）、取引区分。

### エラー処理
- 取得0件で `OlapNoDataError`、通信失敗で `OlapFetchError`/`RuntimeError`。デバッグログに詳細。

### 注意点
- ㎡/総㎡ はOLAPから取得せずアプリ側で計算（`TKS_VOUCHER_OLAP_ENABLED_OP_FIELDS=OP区分,商品コード`）。

## 5. 伝票作成・印刷画面の一覧管理

### 概要

4. 行データ変更で更新時刻記録・保存（`_on_row_data_changed`/`_save_records_if_ready`）。
5. フィルタ（受注No検索・登録状態）で表示制御（`_apply_filters`）。

### 使用クラス・関数
| ファイル | クラス／関数 | 役割 |
| --- | --- | --- |
| app/voucher_window.py | `_add_row` / `_collect_row` | 行UI・収集 |
| app/voucher_window.py | `_save_records` / `_restore_saved_records` | 一覧の永続化 |
| app/voucher_window.py | `_apply_filters` / `_sort_rows_by_updated_at` | 表示制御 |

### 入力／出力
- 入力：ユーザ操作、保存済みレコードJSON。
- 出力：一覧表示、保存レコード（work配下）。

### エラー処理
- 保存・復元失敗はログ出力し処理継続（`logging`）。

### 注意点

## 7. 伝票PDF生成処理

### 概要
選択伝票（01〜08）のPDFをreportlab描画＋テンプレートPDFオーバーレイで生成する。`app/voucher_service.py`

### 処理フロー
1. `build_vouchers_pdf_bytes(voucher_ids, data)` / `create_vouchers_pdf(...)` を呼ぶ。
2. テンプレート存在チェック（`_check_templates`）。
3. 各伝票IDごとにreportlabでフォーム描画またはテンプレートPDFへオーバーレイ。
   - 01（売上伝票）：アプリ描画方式（`_draw_form_01`）。
   - 02-08：テンプレートPDFへ重ね描き（`_overlay_on_template`）。
   - 指図書系（03/04/05）：編集オブジェクトを重ね描き（`_draw_edit_objects`）。
4. PDFバイト列を結合（`merge_pdf_bytes`）。
5. `create_vouchers_pdf` はファイル保存（タイムスタンプ＋受注No）。

### 使用クラス・関数
| ファイル | クラス／関数 | 役割 |
| --- | --- | --- |
| app/voucher_service.py | `create_vouchers_pdf` / `build_vouchers_pdf_bytes` | PDF生成 |
| app/voucher_service.py | `_assemble_pdf_bytes` / `_draw_edit_objects` | 描画・組立 |
| app/voucher_data_mapper.py | `build_voucher_pages` / `_build_page` / `_detail_row` | 印字データ生成 |
| app/voucher_templates.py | `VOUCHER_TYPES` / 座標定数 | レイアウト定義 |

### 入力／出力
- 入力：伝票ID、印字データ（pages）、編集オブジェクト、テンプレートPDF（`img/sample_denpyou_NN.pdf`）。
- 出力：PDFバイト列／PDFファイル。

### エラー処理
- 伝票未選択で `ValueError`、テンプレ欠如で `FileNotFoundError`、保存失敗で `RuntimeError`。

### 注意点
- CIDフォント（HeiseiKakuGo-W5）は✔等の記号字形を持たないため記号はベクター線で描く（`draw_symbol_text`）。
- 出力先が Program Files/_internal 配下は不可（`ensure_voucher_output_dir`）。

## 14. Kintone既存データ確認処理

### 概要
登録前に同一受注Noの既存kintoneレコードを検索し、確認画面へ反映する。`app/kintone_client.py` + `app/kintone_existing.py`

### 処理フロー
1. `WorkerThread.run` 内で `fetch_existing_records_by_order_numbers(受注No群)`。
2. kintone `records.json` を `受注No in (...)` で検索（500件ずつページング）。
3. フィールドコード→CSV列名へ逆引き（`_record_to_csv_row`）。
4. `merge_existing_kintone_records_into_preview_rows` で確認画面行へ反映。
   - 受注No単位：仕上日・出荷区分・得意先選択（最初に値のあるレコード採用）。
   - 行単位（検索キー一致）：加工種類のみ。
   - ㎡/総㎡・加工名・加工mmは反映せずOLAP/マスタから再計算。
5. 検索失敗時は続行/中止を確認（`on_pending_registration`）。

### 使用クラス・関数
| ファイル | クラス／関数 | 役割 |
| --- | --- | --- |
| app/kintone_client.py | `fetch_existing_records_by_order_numbers` | 既存検索 |

## 23. アップデート処理

### 概要
kintone（更新管理アプリ）からバージョン確認・インストーラ取得・直接起動する。`app/update_client.py`

### 処理フロー
1. `UpdateClient.check_for_update(現バージョンコード)` で `app=250` を問い合わせ。
2. バージョンコード比較で新版判定。
3. `download_installer` で本体プロセスがインストーラを updates フォルダへDL（`.part`→本ファイル）。
4. `launch_installer_for_update` で Inno Setup をサイレント（`/VERYSILENT` 等）直接起動。
5. 起動成功で `quit_app_for_update` により本体終了。失敗は警告（本体は終了しない）。

### 使用クラス・関数
| ファイル | クラス／関数 | 役割 |
| --- | --- | --- |
| app/update_client.py | `check_for_update` / `download_installer` / `launch_installer_for_update` | 更新 |
| app/update_helper.py | `run_update`（with-helperビルド用） | 補助プロセス |
| app/build_features.py | `updates_enabled` / `build_variant` | ビルド種別 |

### 入力／出力
- 入力：バージョンコード、APIトークン。出力：インストーラ、`update_installer.log`。

### エラー処理
- インストーラ名がsetup/installer/installを含まないと拒否。起動失敗時は本体を終了せず案内。

### 注意点
- PowerShell・外部ヘルパーEXEを使わない方式が標準（コメント明記）。トークン等はログに出さない。
