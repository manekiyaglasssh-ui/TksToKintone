## 3. 伝票データ（OLAPレスポンス → PDF用データ変換）

根拠：`app/voucher_data_mapper.py`

### 3.1 変換の流れ
1. `extract_r1_rows` でOLAPレスポンスからR1行（内部エイリアスキー）を抽出。
2. `build_voucher_pages` で受注No・伝票No単位にグルーピングし `FORM_DETAIL_ROWS`(7) 行ずつページ化。
3. `_build_page` でページヘッダー値、`_detail_row` で明細値を生成。

### 3.2 内部キー／表示名／フォールバック
- OLAP表示No→内部エイリアスの対応は `templates/voucher_olap_request.json` の `R1List`（OLAP表示No/OLAP表示名）から動的ロード（`_load_r1_display_alias_keys`）。
- 値取得 `_v(row, alias)` はエイリアス→数値キー（例 `order_no`/`6`）のフォールバックを持つ。

主な内部キー（`_build_page`/`_detail_row`）：

| 内部キー | 表示用途 | 備考 |
| --- | --- | --- |
| order_no | 受注No | QRコード元 |
| customer_code / customer_name | コードNo / 得意先名 | |
| customer_order_no_10 | お客様注文No | 1.2倍表示 |
| delivery_date / voucher_no | 納品日 / 伝票No | |
| trade_type / ship_type | 取引区分 / 出荷区分 | |
| operator / sales_rep / construction_rep | 入力者名 / 担当 | |
| transaction_type | 取引区分（移動伝票=8制御） | 得意先コードから取得 |
| product_name / product_note | 品名 / 寸法 | name=="*"は空扱い |
| ordered_quantity / quantity_unit_name | 数量 / 単位 | |
| op_type | OP区分 | 00/01/02 |
| sales_unit_price / purchase_unit_price | 摘要上段/下段 | 合計算出元 |

### 3.3 計算項目（㎡/総㎡・単価/金額）
`resolve_unit_and_amount_values`（OP区分による分岐）：
- **OP区分 02**：W×Hから算出した 02時平米 / 02時総平米。
- **OP区分 01**：統計数量 / 受注統計数量（0なら02時平米/02時総平米へフォールバック）。
- **OP区分 00**：単位名称が「ケース/ロット」なら 00時ケース・ロット平米、他は統計数量。
- **OP区分なし**：固定値1を入れず空欄（登録の `area_calculator` も同様）。
- 表示は小数第3位で四捨五入し0/空は空文字（`_format_unit_display` / `format_area_3`）。

### 3.4 空欄時の扱い
- 商品名称が `"*"` の明細行は数量・単価・金額・㎡を空欄にする。
- 日付 `0000/00/00` 等は空文字（`format_date_yy_mm_dd`）。
- ダッシュ `-` は空に変換（`_blank_if_dash`）。

## 4. 登録CSVデータ（OUTPUT_HEADERS）

根拠：`tks_to_kintone/transform.py`

- 入力ヘッダー（SOURCE_HEADERS）：受注No/受注行No/硝・加工/商品コード/商品名称/W寸法/H寸法/掛率集計コード/名称/受注数量/㎡/総㎡/OP区分 ほか。
- 出力ヘッダー（OUTPUT_HEADERS）：上記＋ 仕上日/出荷区分/工程/検索キー/発注コード_照合/発注コード_本社判定/加工判定/洗浄区分/判定/OP区分 など。
- `工程` 列はkintone送信対象外（`EXCLUDED_CSV_HEADERS`）。
- `OP区分`/`総重量` は必須列チェック対象外（旧抽出CSV互換、`OPTIONAL_SOURCE_HEADERS`）。
- kintone登録キーは `検索キー`（updateKey）。受注Noは `受注No`。

## 5. 指図書編集データ

根拠：`app/voucher_edit_objects.py`, `app/line_decorations.py`

### 5.1 保存形式
- 受注Noごとに1ファイル：`work/voucher_edit_objects/<受注No>.json`。
- オブジェクト配列。座標は scene座標系（原点=ページ左上、単位pt、`PAGE_W×PAGE_H`）。PDF生成時のみreportlab座標（左下原点）へ変換。
- 共通メタ：`coordinate_origin="scene_top_left"`, `geometry_basis="object_geometry_v2"`, `created_at`/`updated_at`, `color`(RGB float)。
- `target_vouchers`（反映先伝票）：既定 `["03","04","05"]`（指図書(1)/指図書(2)/梱包明細書）。

### 5.2 オブジェクト種別（`OBJECT_TYPES`）

| type | 主な属性 | 説明 |
| --- | --- | --- |
| text | x/y/width/height, text, font_family, font_size, font_bold/italic, text_color, text_align(left固定), vertical_align(top固定), line_width, stroke_color, fill_color, auto_fit, manual_resized | テキストボックス |
| symbol_text | x/y(中心アンカー), text, font_size, anchor="center" | 記号テキスト（✔等。PDFはベクター描画） |
| line | x1/y1/x2/y2, line_width, stroke_color, line_type | 線。line_type=line/arrow/double_arrow/double_line |
| rectangle | x/y/width/height, 内部text, line_width, fill_color | 四角（内部テキスト可） |
| ellipse | x/y/width/height, 内部text, line_width, fill_color | 丸（内部テキスト可） |
| image | x/y/width/height, image_format, image_data(base64) | 画像（透過/二値化対応） |
| freehand | points([[x,y]...]), line_width, stroke_color | 単独手書きパス |
| freehand_layer | layer_id, layer_name, pen_width, stroke_color, visible, locked, strokes[{points,pen_width,stroke_color}] | 手書きレイヤー |

### 5.3 線種（line_decorations）

| line_type | 説明 |
| --- | --- |
| line | 単純な直線 |
| arrow | 終点側に矢じり |
| double_arrow | 両端に矢じり |
| double_line | 2本の平行線（間隔 `DOUBLE_LINE_GAP=3.5pt`） |

矢じり：長さ12pt、開き角26度（`ARROW_HEAD_LENGTH`/`ARROW_HEAD_ANGLE`）。

### 5.4 互換処理
- 旧JSON（id無し・w/h無し・line_type無し）は読み込み時に既定値補完（`_with_compat_defaults`）。
- 同一IDは最初の1件のみ採用（重複防止）。
- 既定値：フォント `Yu Gothic UI` / 12pt、線幅1.0、ペン幅3.0、色 `#000000`。

## 6. OLAPキャッシュデータ

根拠：`app/voucher_cache.py`

`work/voucher_cache/<受注No>.json`：
```
order_no, fetched_at(ISO), request_conditions, row_settings(仕上日/AM・PM/加工名チェック/印刷伝票チェック), raw_rows(抽出直後), pages(マッピング後)
```
- 編集オブジェクトとは別ディレクトリに保存（キャッシュ削除で編集内容が消えないため）。
- 既定保存期間60日（`DEFAULT_CACHE_RETENTION_DAYS`）。
