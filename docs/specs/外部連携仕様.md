# 外部連携仕様

対象アプリ：**TKS OLAP to kintone**（v1.4.16）

> OLAP / Kintone / Teams / アップデート の外部連携をソースコードから整理する。推測箇所は明記。

---

## 1. OLAP連携

根拠：`app/tks_client.py`, `app/voucher_olap_service.py`, `app/voucher_data_mapper.py`, `templates/voucher_olap_request.json`, `docs/olap/`

### 1.1 接続方式
- `TKS_CLIENT_MODE` で切替：
  - `mock`：`file://` のローカルCSVを使用（`MockTksClient`）。TKS実接続なし。
  - `http`：TKS OLAPへ実接続（`HttpTksClient`、requests.Session）。
- ベースURL `TKS_BASE_URL` に以下のパスを付与：
  - ログイン：`/c/ログイン認証`（POST）
  - OLAPデータ：`/c/OLAPデータ`（PUT）

### 1.2 ログイン
- `HttpTksClient.login(run_input)`：ログインpayloadをPOST。
- 成功判定：`ResponseData.Ｘ0`(=`X0`) == `"00"`。
- `.ASPXAUTH` Cookieの取得有無をログ出力。
- 送信payloadはデバッグJSONへ保存（パスワードは `_mask_login_payload` でマスク）。
- 認証区分 `TKS_LOGIN_AUTH_KBN`、端末識別ID `TKS_TERMINAL_ID`、コンピュータ名・IPを送信。

### 1.3 伝票データ取得（伝票画面）
- `VoucherOlapService.fetch_voucher_rows(order_no)`：
  1. `_build_voucher_payload` でテンプレートのR2条件に受注Noを差し込む。
  2. `/c/OLAPデータ` へ PUT（timeout 120秒）。
  3. `_extract_voucher_rows_or_raise` でR1行抽出。0件なら `OlapNoDataError`。
- R1にはOP区分・商品コードを含める（㎡/総㎡はアプリ側計算）。

### 1.4 加工データ取得（Kintone登録）
- `HttpTksClient.fetch_csvs`：加工抽出CSV・素板抽出CSVをOLAPから取得。
- mockモードは `TKS_KAKOU_CSV_URL`/`TKS_SOBA_CSV_URL`（file://）から読む。
- テンプレート：`TKS_KAKOU_REQUEST_TEMPLATE` / `TKS_SOBA_REQUEST_TEMPLATE`（既定 `docs/olap/*.json`）。

### 1.5 取引区分取得
- `fetch_transaction_type_by_customer_code(customer_code)`：得意先マスタ別テーブルへ問い合わせ。
- payloadは `build_transaction_type_payload`、結果は `parse_transaction_type` で解析。
- 得意先コード単位でキャッシュ（同一コードの重複問い合わせ回避）。
- 取引区分は移動伝票（取引区分=8）のPDF表示制御に使用。

### 1.6 使用テンプレート
- `templates/voucher_olap_request.json`：R1List（OLAP表示No/表示名）→内部エイリアスのマッピング元。
- `docs/olap/kakou_request_template.json` / `soba_request_template.json`：実リクエストテンプレ（起動時にProgramDataへ再配置）。

### 1.7 送信payload補完
- `_ensure_customer_order_no_column`：客先注文No列を補う。
- OP関連列の制御：`_remove_op_related_columns` / `_keep_only_enabled_op_columns` / `_remove_calc_op_columns`（`TKS_VOUCHER_OLAP_ENABLED_OP_FIELDS` に従う）。
- `_remove_blank_sales_month_condition`：空の売上月条件を除去。

### 1.8 レスポンス変換
- `extract_r1_rows` → 内部エイリアスキーの行リスト。
- `_r1_list` / `_raw_r1_rows`：ResponseData.R1List（dict/list両対応）を正規化。
- 表示用整形：`format_date_yy_mm_dd` / `format_number` / `format_month_day`。

### 1.9 エラー処理
- 取得0件 `OlapNoDataError`、通信失敗 `OlapFetchError`/`RuntimeError`。
- リクエスト/レスポンスをデバッグJSON・ログに記録（`_log_request_diagnostics`/`_log_response_diagnostics`）。
- 失敗時はメッセージにデバッグファイルパスを含める。

## 2. Kintone連携

根拠：`app/kintone_client.py`, `app/kintone_existing.py`, `templates/field_mapping.json.sample`

### 2.1 接続先
- ドメイン：`KINTONE_DOMAIN`（既定 manekiya.cybozu.com）。
- アプリID：`KINTONE_APP_ID`（sampleでは 255=テスト想定。本番は 211 が `teams_notifier` で参照）。
- 認証：HTTPヘッダ `X-Cybozu-API-Token`（`KINTONE_API_TOKEN`）。

### 2.2 接続確認
- `check_connection`：`/k/v1/app.json` をGET（200で成功）。機能選択画面のkintone認証で使用。

### 2.3 既存データ確認
- `fetch_existing_records_by_order_numbers(受注No群)`：
  - `/k/v1/records.json` を `受注No in ("...","...") limit 500 offset N` で取得（500件ずつページング）。
  - フィールドコード→CSV列名へ逆引き（`_reverse_mapping`/`_record_to_csv_row`）。
- 反映ルール（`kintone_existing`）：
  - 受注No単位：仕上日・出荷区分・得意先選択（`ORDER_LEVEL_FIELDS`、最初に値があるレコードを採用）。
  - 行単位（検索キー一致）：加工種類のみ（`ROW_LEVEL_FIELDS`）。

### 2.4 登録／更新
- `register_rows`：日付正規化→100件（`BATCH_SIZE`）ずつ `/k/v1/records.json` を PUT（`upsert: true`）。
- updateKey は「検索キー」フィールド（`SEARCH_KEY_HEADER`）。
- INSERT/UPDATE件数をレスポンスから集計しログ。

### 2.5 反映対象項目 / 反映しない項目

| 区分 | 項目 | 扱い |
| --- | --- | --- |
| 反映する（既存→確認画面） | 仕上日・出荷区分・得意先選択・加工種類 | 人が編集しうる項目 |
| 反映しない | ㎡・総㎡ | 常にOP区分で再計算（過去不具合で1が残る対策） |
| 反映しない | 加工名・判定加工名・加工mm | OLAP/マスタから再判定 |
| 送信しない | 工程 | `EXCLUDED_CSV_HEADERS` |
| 送信しない | 空文字フィールド | `_to_record` で除外 |

### 2.6 日付正規化
- `normalize_kintone_date`：`%Y-%m-%d`/`%Y/%m/%d`/`%Y%m%d`/`YYYY年M月D日` を `%Y-%m-%d` へ。
- 空相当（`""`,`null`,`-`,`0`,`0000/00/00` 等）は空文字。対象：仕上日・発注日・入庫日・納品日・売上日。

### 2.7 field_mapping補完
- `supplement_field_mapping`：不足する標準エントリ（加工名/加工mm/加工種類/得意先選択）を自動追加（既存は上書きしない）。

### 2.8 エラー処理
- requests未導入時は `RuntimeError`。
- HTTPエラーはステータス・本文をログ、バッチ単位で失敗集計し失敗CSVを出力。
- 検索キー空の行は `ValueError`。

## 3. Teams通知

根拠：`app/teams_notifier.py`, `app/voucher_window.py`

### 3.1 通知タイミング
- kintone登録完了時（`registration_completed` → 伝票画面 `notify_kintone_registration_completed` → `_notify_teams_registration_completed`）。

### 3.2 通知内容
- Adaptive Card（`build_teams_order_links_payload`）。
- 各受注Noを「受注No（ラベル）」のテキストにし、kintone絞り込みURL（`build_kintone_order_url`）へのリンク化。
- URLは登録先（test/production）に応じたアプリURL（211/255）＋ビューID20＋並び順指定。

### 3.3 Webhook設定（テスト／本番=東大阪）
- 既定値はコード同梱（`DEFAULT_TEAMS_TEST_WEBHOOK_URL` / `DEFAULT_TEAMS_PROD_WEBHOOK_URL`、本番名は「東大阪」）。
- 環境変数 `TKS_TEAMS_WEBHOOK_URL_TEST_DEFAULT` / `_PROD_DEFAULT` が優先。
- 利用者が設定画面で変更した値（QSettings `teams/webhook_url_*`）が最優先。
- 登録先の判定：`_current_kintone_target` / `_teams_webhook_url_for_current_kintone_target`。

### 3.4 エラー処理・ログ注意
- 送信失敗は `TeamsNotifyError`。
- **Webhook URLはログ・エラーに出力しない**（`post_teams_webhook` は失敗時も「Teams通知に失敗しました」のみ記録）。

## 4. アップデート処理

根拠：`app/update_client.py`, `app/update_helper.py`, `app/build_features.py`, `installer/tks-to-kintone.iss`

### 4.1 バージョン確認
- `UpdateClient.check_for_update(現バージョンコード)`：
  - kintone更新管理アプリ（ドメイン `manekiya.cybozu.com`、アプリ `250`、専用APIトークン）の `records.json` を `アプリ名 in ("TksToKintone") order by バージョンコード desc` で取得。
  - レコードの「バージョンコード」を比較し、現行より大きい最大版を返す。
  - 添付ファイル（「APKファイル」フィールド）から fileKey/name/size を取得。

### 4.2 インストーラ取得
- `download_installer`：本体プロセスでインストーラを `%LOCALAPPDATA%/Manekiya/TksToKintone/updates` へDL（`.part`→本ファイルへ置換）。
- ファイル名に `setup`/`installer`/`install` を含まないと拒否（署名済みインストーラ要件）。

### 4.3 起動方法
- `launch_installer_for_update`：Inno Setup を直接サイレント起動（`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- /LOG=...`）。
- DETACHED_PROCESS / CREATE_NO_WINDOW で起動。
- 起動成功で本体終了（`quit_app_for_update`）。失敗時は警告し本体は終了しない。

### 4.4 PowerShellを使わない仕様
- 外部スクリプト/helper EXE を使わず通常プロセス起動とファイル操作のみで完結（`update_client` 冒頭コメント）。
- `update_helper.py`（`tks_update_helper.exe`）は `with-helper` ビルド用の別系統補助プロセス。親プロセス終了待ち→インストーラ起動→本体再起動を行う。コマンドラインに秘密情報を渡さない。

### 4.5 ログ出力
- インストーラログ：`%PROGRAMDATA%/Manekiya/TksToKintone/logs/update_installer.log`。
- ヘルパーログ：`%LOCALAPPDATA%/Manekiya/TksToKintone/logs/update_helper.log`。
- 秘密情報（トークン等）はログに出さない。

### 4.6 ビルド種別による制御
- `build_features.build_variant()`：`build_variant.txt` または環境変数 `TKS_BUILD_VARIANT`。
- `no-update` ビルドは更新機能無効（`updates_enabled()` False）。
